# KubeVM autoscaling design and implementation tasks

**Status**: Draft; **Epic**: TBD. All shipping tasks have **Ticket: TBD** pending real stories linked to an epic before merge. The author requested drafting without creating an epic. Do not fabricate identifiers.

Read [design.md](design.md), [spec.md](spec.md), [model.md](model.md), and [plan.md](plan.md) before implementation. This list is a proposed handoff, not an instruction to implement now. Resolve named gates before dependent work; do not invent provider contracts. Preserve spec 012 as a separate delivery proposal. Paths below denote the owning KubeVM source module once Q1 is resolved, not vendored copies in this checkout. Keep all new behavior feature-gated; include corresponding E2E in each behavioral PR. No automatic commit, push or cluster enablement is authorized by this file.

- [ ] **T001 — Tracking and source ownership (Q1).** Files: this folder and INDEX.md. Depends: none. Record real epic/stories when supplied, final set name, owning repository, API version and branch. Done when the implementation destination and version strategy are unambiguous. Acceptance: AC03, AC05.
- [ ] **T002 — Instantiation contract (Q1).** Files: model.md, provider contract schemas/tests. Depends: T001. Specify immutable templates, permitted fields, UID linkage, authorization and create/delete race protocol. Prove recovery at each pair-creation interruption and reject name/owner collisions. Acceptance: AC01–AC03, AC09.
- [ ] **T003 — Observations and readiness (Q2/Q3).** Files: model.md, research.md, provider conformance fixtures. Depends: T001. Define CPU normalization, timestamps/skew, application-ready evidence and retirement requirements. Record portable memory decision separately; memory work stays blocked until comparable sources are demonstrated. Acceptance: AC05–AC08, AC10.
- [ ] **T004 — Generic set API and controller.** Files: owning API types/generated CRDs, workload package, set controller, admission/tests. Depends: T002. Implement scale mapping, immutable templates, ownership-only membership, bounded pair instantiation/deletion and finalizer recovery. Ship E2E for manual count changes and partial failures. Acceptance: AC01–AC03, AC14.
- [ ] **T005 — Provider extensions.** Files: provider template/admission, telemetry, linkage/readiness, conformance tests; vSphere calls only in its provider package. Depends: T002, T003. Implement CPU reports and declared readiness, UID-safe binding and optional capability discovery. Add memory only after Q2 decision. Existing providers lacking extensions must still manage individual VMs. Acceptance: AC05, AC06, AC08, AC11.
- [ ] **T006 — Autoscaler API and authority.** Files: owning API/CRDs, admission, target claim package/tests. Depends: T004. Validate one UID-bound same-namespace policy per target, SAR and bounds; protect parent and `/scale` count updates. Demonstrate claim/write interleavings with concurrent integration tests. Acceptance: AC04, AC09, AC10.
- [ ] **T007 — Measurement reader and policy engine.** Files: generic contract/reader/cache and autoscaling policy packages/tests. Depends: T003, T005. Implement bounded per-GVK watch registration and UID-keyed samples, coverage/generation/readiness validation, ratio/max logic, protection windows and conservative restart behavior. Inject a clock. Acceptance: AC06–AC08, AC13.
- [ ] **T008 — Autoscaler reconcile and diagnostics.** Files: thin generic controller, status/events/metrics, integration and E2E tests. Depends: T006, T007. Recompute after conflicts, write only generic `/scale`, implement suspension/release and blocked reasons; prove no writes during nonconvergence or invalid telemetry. Acceptance: AC04, AC07–AC10, AC14.
- [ ] **T009 — Hosting and installer (Q4).** Files: embedding manager registration, feature config, RBAC, actual Supervisor installer identified in research.md. Depends: T004, T005, T008. Establish one generic authority across providers, gate capability activation, retain CRDs/finalizers on disablement and isolate collector work. Measure incremental manager resources before changing requests/limits. Acceptance: AC11–AC13.
- [ ] **T010 — Portability and scale qualification.** Files: conformance/E2E/performance suites and research.md. Depends: T009; memory requires Q2; retirement requires Q3. Run both provider implementations, slow/stale metrics, blocked finalizers, pressure and peak scale-out. Record supported count/cadence and status-publication impact. If transport fails the budget, amend design before implementation changes. Acceptance: AC01–AC14.
- [ ] **T011 — Upgrade and operational handoff.** Files: installer lifecycle tests, compatibility matrix, operational docs, this folder. Depends: T010. Test mixed versions, leader loss, history recovery, disable/re-enable and supported rollback. Document parallel-set migration from VM Service, explicit absence of in-place adoption, and future Deployment authority. Replace placeholders before merge; leave unavailable qualification evidence open. Acceptance: AC09–AC14.
